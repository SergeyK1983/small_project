## Small-project
---
#### Общее описание

Небольшой проект (асинхронное веб приложение) для отработки аутентификации и авторизации на базе JWT токенов и имитация платежной системы. 

#### Стек:

- python 3.13
- poetry>=2.0.0
- фреймворк - Fastapi
- база данных - PostgreSQL + sqlalchemy + asyncpg
- миграции - alembic
- административная панель - sqladmin
- аутентификация - pyjwt + argon2-cffi + алгоритм EdDSA
- cli задачи - typer
- тесты - pytest + pytest-asyncio + factory-boy
- фронтенд - jinja2 + css + js
- docker-compose
- nginx

#### Описание
В приложении реализована работа со следующими сущностями: пользователь, администратор, счет, платеж. Счет имеет баланс и привязан к пользователю. Платеж привязан к счету, имеет сумму пополнения/списания и уникальный номер транзакции. 

Пользователь может:
- зарегистрироваться в системе
- войти в систему (username/email, password)
- получить данные о себе
- изменить совои данные, сменить пароль, удалить себя ("мягкое" удаление)
- просмотреть свои счета и операции по счету

Администратор может:
- войти в систему (username/email, password)
- получить данные о себе
- изменить совои данные, сменить пароль, удалить себя ("мягкое" удаление)
- просмотреть список пользователей
- просмотреть список счетов пользователя с балансами
- создать для пользователя счет
- удалить пользователя полностью

При входе в систему пользователь получает access_token. Для текущего фронтенда токен устанавливается в cookie (httponly). Возможна передача токена через заголовок. Доступ к ресурсам приложения организован на основе payload токена.

В приложении реализован endpoint эмулирующий обработку вебхука от сторонней платежной системы. Структура json-объекта для обработки вебхука состоит из следующих полей:

```
transaction_id - уникальный идентификатор транзакции в “сторонней системе”
account_id - уникальный идентификатор счета пользователя
user_id - уникальный идентификатор счета пользователя
amount - сумма пополнения счета пользователя
signature - SHA256 хеш подпись объекта
```
Правило для signature: `{account_id}{amount}{transaction_id}{user_id}{secret_key}`

При обработке вебхука:
- проверяется подпись объекта
- проверяется существует ли пользователь и его счет
- сохраняется транзакция в БД
- начисляется сумма (пополнение/списание) на счет пользователя

#### Развертывание
Вариант 1 (docker compose):
- клонировать репозиторий
- архив **fake_secrets** разархивировать и переименовать в **secrets**
- заполнить файл .env согласно .env.example
- выполнить `docker-compose up -d`
- в браузере перейти по адресу `localhost:8090/dev`

Вариант 2:
- удостоверится, что у вас есть python 3.13 и poetry >= 2.0
- клонировать репозиторий
- архив **fake_secrets** разархивировать и переименовать в **secrets**
- заполнить файл .env согласно .env.example
- выполнить `docker-compose up -d --build --no-deps postgres`
- задать python для проекта, находясь в папке проекта выполнить: `pyenv local 3.13.4`, `poetry env use $(pyenv which python)`
- установить библиотеки `poetry install`
- установить миграции: `alembic upgrade head`
- создать администратора командой `python -m src.cli createsuperuser admin admin`, в данном случае username=admin, password=admin
- запуск `uvicorn src.main:app --host localhost --port 8000`

примечание:
для запуска тестов локально в развернутом postgresql необходимо вручную создать БД с наименованием **test_db** и владельцем $SMPR_POSTGRES_USER
